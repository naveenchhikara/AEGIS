Create `src/data-access/rbia-scoring.ts` following the 5-step DAL pattern:

1. **Import block:**
   - `import "server-only";`
   - `import { prismaForTenant } from "./prisma";`
   - `import type { AuthSession as Session } from "@/lib/auth";`

2. **Export types:**
   - `BranchRbiaScoreData`: `{ id, compositeScore: number, ratingBand: string, moduleScores: Record<string, number>, frozenAt: Date | null, frozenById: string | null, engagementId: string }`
   - `EngagementModuleScoreRow`: `{ moduleCode: string, moduleName: string, nodeId: string, responseCount: number, totalLeafCount: number, scoredCount: number }` — for progress display

3. **`getBranchScoreHistory(session, branchId): Promise<BranchRbiaScoreData[]>`**:
   - `db.branchRbiaScore.findMany({ where: { tenantId, branchId, frozenAt: { not: null } }, orderBy: { frozenAt: "desc" } })`.
   - Select: `id, compositeScore, ratingBand, moduleScores, frozenAt, frozenById, engagementId`.
   - Convert `compositeScore: Number(row.compositeScore)`.
   - Cast `moduleScores` from JSON to `Record<string, number>` (it's already stored as `{ "OPS": 0.85, ... }`).

4. **`getEngagementBranchScore(session, engagementId): Promise<BranchRbiaScoreData | null>`**:
   - `db.branchRbiaScore.findUnique({ where: { engagementId } })`.
   - Note: `engagementId` is `@unique` on BranchRbiaScore, so findUnique works. Still filter tenantId at application level: after fetch, verify `result.tenantId === tenantId` before returning (defense in depth). If mismatch, return null.
   - Convert Decimal fields same as above.

5. **`getEngagementModuleScores(session, engagementId): Promise<EngagementModuleScoreRow[]>`**:
   - **Use bulk findMany + TypeScript grouping** (NOT N+1 per module):
   - Query 1: Load all module-level ExaminationNodes (depth=1, isActive=true) for the tenant — `db.examinationNode.findMany({ where: { tenantId, depth: 1, isActive: true } })`.
   - Query 2: Load all active leaf nodes for the tenant in a single query — `db.examinationNode.findMany({ where: { tenantId, isActive: true, isLeaf: true }, select: { id: true, path: true } })`. Group by module path prefix (first segment of `path`) in TypeScript.
   - Query 3: Load all responses for this engagement — `db.examinationResponse.findMany({ where: { engagementId }, select: { nodeId: true } })`. Join with leaf nodes from Query 2 to determine which module each response belongs to.
   - Tenant isolation for responses: filter via node's tenantId (Query 2 already scoped to tenantId).
   - Combine: for each module from Query 1, count total leaves (from Query 2) and scored responses (from Query 3) to build progress rows.
   - Return array with progress counts per module.

IMPORTANT: Every function accepts `session: Session` as first arg and extracts `tenantId`. Every query includes `WHERE tenantId` where applicable (BranchRbiaScore has tenantId; ExaminationResponse inherits via engagement — verify tenant via engagement join or explicit tenantId field).

NOTE: `ExaminationResponse` model does NOT have a direct `tenantId` field. Tenant isolation for responses is enforced via the engagement relation (`engagement.tenantId`). For response queries, either join through engagement or use the node's tenantId.
