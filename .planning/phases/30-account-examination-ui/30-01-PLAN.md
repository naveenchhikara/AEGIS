**Functions to implement:**

**a) `getAccountsWithProgress(session, engagementId, moduleCode)`**

Returns sampled loan accounts with completion counts for the sidebar list.

```typescript
export type AccountWithProgress = {
  id: string;
  accountNo: string;
  borrowerName: string;
  outstandingAmount: number;
  dpd: number;
  assetClass: string;
  totalQuestions: number; // count of active questions for this module
  answeredQuestions: number; // count of AccountExamResponse records for this account
  violationCount: number; // count of VIOLATION responses for this account
};
```

Query approach:

1. Get sampled accounts: `LoanAccount WHERE engagementId AND moduleCode AND isSampled = true AND tenantId`
2. Count active questions: `ExaminationQuestion WHERE tenantId AND moduleCode AND isActive = true` — single count, same for all accounts
3. For each account, count responses: Use `_count` on `accountExamResponses` relation, or do a raw count query
4. Better approach: Use a single query with `include: { _count: { select: { accountExamResponses: true } } }` plus a sub-count for violations

Efficient implementation: Two queries — one for sampled accounts with `_count`, one for the total active question count. Then a third query grouping violations by loanAccountId:

```typescript
const db = prismaForTenant(extractTenantId(session));

const [accounts, questionCount, violationCounts] = await Promise.all([
  db.loanAccount.findMany({
    where: { engagementId, moduleCode, isSampled: true, tenantId },
    select: {
      id: true,
      accountNo: true,
      borrowerName: true,
      outstandingAmount: true,
      dpd: true,
      assetClass: true,
      _count: { select: { accountExamResponses: true } },
    },
    orderBy: { accountNo: "asc" },
  }),
  db.examinationQuestion.count({
    where: { tenantId, moduleCode, isActive: true },
  }),
  db.accountExamResponse.groupBy({
    by: ["loanAccountId"],
    where: { engagementId, tenantId, status: "VIOLATION" },
    _count: true,
  }),
]);
```

Map results: convert Decimal fields with `Number()`, merge violation counts from the groupBy, set `totalQuestions` from the single count.

Query: Active questions for the module + LEFT JOIN responses for this specific account:

```typescript
const questions = await db.examinationQuestion.findMany({
  where: { tenantId, moduleCode, isActive: true },
  include: {
    accountExamResponses: {
      where: { loanAccountId, engagementId },
      select: { id: true, status: true, note: true, respondedAt: true },
      take: 1, // Unique constraint ensures 0 or 1
    },
  },
  orderBy: { displayOrder: "asc" },
});
```

Map: flatten `accountExamResponses[0]` to `response` field, convert Decimal weight to number.

**`saveAccountExamResponse(input: SaveAccountExamResponseInput)`:**

1. `getRequiredSession()` — extract session, tenantId, userId
2. Permission check: user must have `"audit_execution:read"` at minimum (both auditors and CAE can save responses)
3. Validate input with Zod schema
4. Verify engagement exists and is in a scoring-allowed status (reuse the `SCORING_ALLOWED_STATUSES` pattern)
5. Verify the loanAccount belongs to this engagement and tenant
6. Upsert `AccountExamResponse` on the unique constraint `[engagementId, loanAccountId, questionId]`:

```typescript
const response = await db.accountExamResponse.upsert({
  where: {
    engagementId_loanAccountId_questionId: {
      engagementId: input.engagementId,
      loanAccountId: input.loanAccountId,
      questionId: input.questionId,
    },
  },
  update: {
    status: input.status,
    note: input.note ?? null,
    respondedById: userId,
    respondedAt: new Date(),
  },
  create: {
    tenantId,
    engagementId: input.engagementId,
    loanAccountId: input.loanAccountId,
    questionId: input.questionId,
    status: input.status,
    note: input.note ?? null,
    respondedById: userId,
    respondedAt: new Date(),
  },
});
```

7. `revalidatePath` for the examination page
8. Return `{ success: true, data: { id: response.id, status: response.status } }`
9. Catch errors, log via `logger`, return `{ success: false, error: message }`

**`addQuestion(input: AddQuestionInput)`:**

1. `getRequiredSession()` — permission check: must have `"audit_execution:manage_sections"` (CAE/HIA only)
2. Validate with Zod
3. Get max displayOrder for this module: `findFirst orderBy displayOrder desc` + 1
4. Create ExaminationQuestion with all fields, `createdById: userId`, `displayOrder: maxOrder + 1`
5. `revalidatePath` for the questions management page
6. Return `{ success: true, data: created question }`

**`updateQuestion(input: UpdateQuestionInput)`:**

1. Permission check: `"audit_execution:manage_sections"`
2. Validate with Zod
3. Verify question exists and belongs to tenant
4. Update only the provided fields (spread only defined keys)
5. `revalidatePath`
6. Return `{ success: true }`

**`deactivateQuestion(input: DeactivateQuestionInput)`:**

1. Permission check: `"audit_execution:manage_sections"`
2. Set `isActive = false` on the question
3. Do NOT delete existing AccountExamResponse records — QMGT-03 requires historical data preservation
4. `revalidatePath`
5. Return `{ success: true }`

**`reactivateQuestion(input: DeactivateQuestionInput)`:**

1. Same pattern as deactivate but sets `isActive = true`
2. Same permission check

All four actions follow the same error handling pattern: try/catch with logger.error and `{ success: false, error: string }` return.
