   - `import type { AuthSession as Session } from "@/lib/auth";`
   - `import type { MeetingType } from "@/generated/prisma";` (or correct enum import path)

2. **Export types:**

   `MeetingAttendee`: `{ name: string, role: string, designation: string }`

   `UpsertMeetingInput`: `{ meetingType: MeetingType, meetingDate: Date, attendees: MeetingAttendee[], minutesText: string | null, keyDiscussionPoints: string | null }`

   `EngagementMeetingData`: `{ id, engagementId, meetingType: MeetingType, meetingDate: Date, attendees: MeetingAttendee[], minutesText: string | null, keyDiscussionPoints: string | null, signedOff: boolean, signedOffById: string | null, signedOffAt: Date | null, createdAt: Date, updatedAt: Date }`

3. **`getEngagementMeeting(session, engagementId, meetingType): Promise<EngagementMeetingData | null>`**:
   - `db.engagementMeeting.findUnique({ where: { engagementId_meetingType: { engagementId, meetingType } } })`.
   - Schema has `@@unique([engagementId, meetingType])` so Prisma generates `engagementId_meetingType` as compound unique name.
   - After fetch, verify `result?.tenantId` matches session tenantId (defense in depth — the compound unique doesn't include tenantId). If mismatch, return null.
   - Cast `attendees` from JSON to `MeetingAttendee[]`.

4. **`getEngagementMeetings(session, engagementId): Promise<EngagementMeetingData[]>`**:
   - `db.engagementMeeting.findMany({ where: { tenantId, engagementId }, orderBy: { meetingType: "asc" } })`.
   - Note: EngagementMeeting has a `tenantId` field, so use it in WHERE for tenant isolation.
   - Cast `attendees` from JSON to `MeetingAttendee[]` on each record.

5. **`upsertEngagementMeeting(session, engagementId, data: UpsertMeetingInput): Promise<EngagementMeetingData>`**:
   - Uses Prisma `upsert` with compound unique:
     ```
     db.engagementMeeting.upsert({
       where: { engagementId_meetingType: { engagementId, meetingType: data.meetingType } },
       create: {
         tenantId, engagementId,
         meetingType: data.meetingType,
         meetingDate: data.meetingDate,
         attendees: data.attendees as any,  // Json field
         minutesText: data.minutesText,
         keyDiscussionPoints: data.keyDiscussionPoints,
         signedOff: false,
       },
       update: {
         meetingDate: data.meetingDate,
         attendees: data.attendees as any,
         minutesText: data.minutesText,
         keyDiscussionPoints: data.keyDiscussionPoints,
       },
     })
     ```
   - The `as any` cast is needed because Prisma Json fields accept `any` for input but the function signature uses the typed `MeetingAttendee[]`.
   - Do NOT update `signedOff` in the update clause — sign-off is a separate action (Phase 20 server action).

IMPORTANT: Verify that the Prisma compound unique where clause syntax is correct. In Prisma 7, compound unique names are the field names joined by underscore: `engagementId_meetingType`.
