**State machine (5 states):**

1. `idle` — Module dropdown + drag-drop zone + template download button visible
2. `mapping` — Column mapping preview shown, user confirms or cancels
3. `importing` — Loading spinner, import in progress
4. `summary` — Import summary shown with results
5. `error` — Error alert shown

**UI structure:**

1. **Module selector** (top): Select/dropdown with module options from MODULE_FIELD_CONFIGS. Default to first option. Must be selected before upload.

2. **Template download button**: Link/button that opens `/api/loan-portfolio/template?moduleCode={selected}` in new tab. Text: "Download Template". Icon: Download from @/lib/icons.

3. **Drag-and-drop zone** (idle state):
   - Dashed border container (border-dashed border-2 rounded-lg p-8)
   - Center: Upload icon + "Drag & drop CSV or Excel file here" + "or click to browse"
   - Accept: .csv, .xlsx
   - On drop/select:
     a. Determine file type (csv vs xlsx) from extension
     b. For CSV: read as text → parseCsvText → get headers + rows
     c. For Excel: read as ArrayBuffer → convert to Buffer → parseExcelBuffer → get headers + rows
     d. NOTE: Excel parsing uses ExcelJS which requires server-side processing. For .xlsx files, read the file as ArrayBuffer on the client, then send it to a lightweight parse endpoint OR use a simpler client-side approach: read the xlsx using the csv-parser approach won't work. Better approach: For .xlsx files, send the raw file to the server action which parses it there. For .csv files, parse client-side for instant feedback.
     e. REVISED approach for Excel: Since ExcelJS is server-side only, use this pattern:
     - CSV: parse client-side with parseCsvText (instant feedback per CONTEXT.md decision)
     - Excel: Use SheetJS/xlsx-style OR simply read xlsx on server. Since the user decision says "client-side validation on file select," use a lightweight approach: for xlsx, read via a POST to a new parse endpoint, or use the `xlsx` npm package client-side. However, ExcelJS is already in the project. SIMPLEST: treat Excel files the same as CSV in terms of flow — parse on client using FileReader → but ExcelJS needs Node.js Buffer.
     - BEST approach given constraints: For CSV, parse client-side. For Excel, send to server for parsing, show a brief loading state, then proceed to mapping preview. Create a small server action `parseUploadedFile` that accepts FormData with the file, parses it server-side, returns { headers, rows }.
       f. After getting headers + rows: call detectColumnMapping(headers, moduleCode) → set state to `mapping`

4. **Column mapping preview** (mapping state):
   - Render ColumnMappingPreview component with the mapping
   - On confirm: call validateAndTransformRows with raw rows + mapping + moduleCode
   - Check if module already has accounts (from existingAccountCounts prop)
   - If existing > 0: show AlertDialog confirmation: "This will replace {N} existing accounts for {module label} at this branch. New file has {M} rows. Continue?"
   - On confirmed (or no existing accounts): call importLoanPortfolio server action with validated rows → transition to `importing` → then `summary`

5. **Import summary** (summary state):
   - Render ImportSummary component
   - On dismiss: reset to idle, refresh page data (router.refresh())

6. **Error state**: Alert with error message and "Try Again" button
