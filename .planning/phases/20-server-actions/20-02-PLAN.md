**saveExaminationResponse** — follows the 5-step pattern:

1. **Auth:** `const session = await getRequiredSession();` — extract userRoles, tenantId
2. **Permission:** `hasPermission(userRoles, "rbia:examine")` — return `{ success: false, error, code: "PERMISSION_DENIED" }` if denied
3. **Validate:** `SaveExaminationResponseSchema.safeParse(input)` — return `{ success: false, error: parsed.error.issues[0].message, code: "VALIDATION_ERROR" }` if invalid
4. **Tenant-scoped Prisma:** `const db = prismaForTenant(tenantId);`
5. **Transaction:** `db.$transaction(async (tx) => { ... })`

Inside the transaction:

- `setAuditContext(tx, { actionType: "examination_response.saved", userId, tenantId, sessionId })`
- Compute `score` from `scoreLabel`: `const score = SCORE_VALUES[validated.scoreLabel];`
- Verify engagement exists and belongs to tenant: `tx.auditEngagement.findFirst({ where: { id: validated.engagementId, tenantId }, select: { id: true, status: true } })`. If not found, throw "Engagement not found". If status is not "IN_PROGRESS", return `{ success: false, error: "Engagement must be in progress", code: "CONFLICT" }`.
- **Upsert** ExaminationResponse on compound unique `(engagementId, nodeId)`:
  ```
  tx.examinationResponse.upsert({
    where: { engagementId_nodeId: { engagementId, nodeId } },
    create: { tenantId, engagementId, nodeId, score, scoreLabel, workingNotes: workingNotes ?? null, flagForObservation, flagForActionPoint, respondedById: session.user.id, respondedAt: new Date() },
    update: { score, scoreLabel, workingNotes: workingNotes ?? null, flagForObservation, flagForActionPoint, respondedById: session.user.id, respondedAt: new Date() },
  })
  ```
- **Silent draft AP creation** (per CONTEXT.md: "silent — no toast or notification"): If `flagForActionPoint` is true, check if a draft AP already exists for this response. If not, create one prefilled from the response:
  ```
  if (validated.flagForActionPoint) {
    const existingAp = await tx.actionPoint.findFirst({
      where: { sourceResponseId: response.id, engagementId: validated.engagementId },
    });
    if (!existingAp) {
      // Load node for module code + description
      const node = await tx.examinationNode.findUnique({
        where: { id: validated.nodeId },
        select: { code: true, name: true, path: true },
      });
      // Atomic serial number
      const maxSerial = await tx.actionPoint.aggregate({
        where: { engagementId: validated.engagementId },
        _max: { serialNo: true },
      });
      const nextSerialNo = (maxSerial._max.serialNo ?? 0) + 1;
      // Need branchId from the engagement
      const eng = await tx.auditEngagement.findFirst({
        where: { id: validated.engagementId },
        select: { branchId: true },
      });
      // Severity suggestion from score
      const severityFromScore = validated.scoreLabel === "NON_COMPLIANT" ? "HIGH" : validated.scoreLabel === "PARTIALLY_COMPLIANT" ? "MEDIUM" : "LOW";
      await tx.actionPoint.create({
        data: {
          tenantId,
          engagementId: validated.engagementId,
          branchId: eng?.branchId ?? "",
          serialNo: nextSerialNo,
          title: node?.name ?? "Action Point",
          description: validated.workingNotes ?? node?.name ?? "",
          severity: severityFromScore,
          moduleCode: node?.path?.split(".")[1] ?? node?.code ?? "",
          sourceResponseId: response.id,
          status: "DRAFT",
          createdById: session.user.id,
        },
      });
    }
  }
  ```
- Return the upserted response id.

After transaction: `revalidatePath(\`/audit-execution/\${validated.engagementId}/rbia\`);`

Return: `{ success: true, data: { id: response.id } }`

Error handling: catch block logs with `logger.error` and returns `{ success: false, error: message, code: "INTERNAL_ERROR" }`.

**Note on engagement status check:** The action should check that the engagement is in IN_PROGRESS status before allowing saves. However, be lenient — also allow OPENING_MEETING, EXIT_MEETING, and REPORT_DRAFT as valid states for scoring (auditors may continue scoring during these phases). Only reject PLANNED, TEAM_ASSIGNED, COMPLETED, and CANCELLED.
