<objective>
## Goal
1. Auto-create ComplianceItem when an observation transitions to ISSUED (ISS-004)
2. Add engagement status transitions with UI controls (ISS-005)
3. Reclassify ISS-002 — compliance lifecycle actions actually exist and are wired to UI

## Purpose

ISS-004: Without auto-creation, observations reaching ISSUED have no compliance tracking. Users must manually trigger batch compliance item creation — easy to forget, leaving orphaned observations.

ISS-005: Engagement status is stuck at PLANNED forever. No way to track audit progress or mark audits complete. Users need "Start Audit" and "Complete Audit" actions.

ISS-002 reclassification: Phase 1 audit reported compliance lifecycle as broken, but all 7 transition actions exist (`submit-branch-response.ts`, `zac-review.ts`, `ace-processing.ts`, `acb-reporting.ts`) and are wired to UI components. This is a false positive — downgrade to resolved.

## Output

- Observations auto-create ComplianceItem on ISSUED transition
- Engagement header shows status transition buttons (Start / Complete / Cancel)
- ISSUES.md updated with ISS-002 reclassification
  </objective>

<acceptance_criteria>

## AC-1: ComplianceItem Auto-Created on ISSUED

Given an observation being transitioned to ISSUED status
When the transition succeeds
Then a ComplianceItem is created with:

- status: OPEN
- dueDate: now + 30 days
- escalationLevel: 0
- daysOpen: 0
- observationId: the observation's ID
- branchId: from observation
- auditId: from observation's engagementId
  And the ComplianceItem creation is non-blocking (try-catch, log on failure)
  And duplicate ComplianceItems are not created if one already exists for the observation

## AC-2: Engagement Status Transitions Work

Given an engagement in PLANNED status
When a user with audit_execution:manage_team permission clicks "Start Audit"
Then the engagement transitions to IN_PROGRESS with actualStartDate set

Given an engagement in IN_PROGRESS status
When a user clicks "Complete Audit"
Then the engagement transitions to COMPLETED with actualEndDate set

Given an engagement in PLANNED or IN_PROGRESS status
When a user clicks "Cancel"
Then the engagement transitions to CANCELLED

## AC-3: Engagement Header Shows Transition Buttons

Given the engagement detail page
When the engagement status is PLANNED
Then a "Start Audit" button is visible (for users with manage_team permission)

Given the engagement status is IN_PROGRESS
Then "Complete Audit" and "Cancel" buttons are visible

Given the engagement status is COMPLETED or CANCELLED
Then no transition buttons are shown

</acceptance_criteria>
