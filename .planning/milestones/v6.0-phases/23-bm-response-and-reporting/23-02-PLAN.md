**Step 1: Create `src/jobs/rbia-overdue-escalation.ts`**

Follow the pattern from `src/jobs/overdue-escalation.ts` exactly.

```typescript
import { prisma } from "@/lib/prisma";
import { prismaForTenant } from "@/data-access/prisma";
```

Export `processRbiaOverdueEscalation()`:

1. Query all tenants: `prisma.tenant.findMany({ select: { id: true, name: true } })`
2. For each tenant, call `processRbiaOverdueForTenant(tenantId)` wrapped in try/catch (log error per tenant, don't fail entire batch)

`processRbiaOverdueForTenant(tenantId: string)`:

1. `const db = prismaForTenant(tenantId)`
2. `const now = new Date()`
3. Find overdue batches: `db.bmResponseBatch.findMany` where `{ tenantId, status: "PENDING", deadline: { lt: now } }`, include `engagement.branch.name`
4. If no overdue batches, return early
5. Find Zonal Auditors: `db.user.findMany` where `{ tenantId, roles: { has: "ZONAL_AUDITOR" as any }, status: "ACTIVE" }`, select `{ id: true, email: true }`
6. For each overdue batch, wrap in `db.$transaction`:
   - Update batch status: `tx.bmResponseBatch.update({ where: { id }, data: { status: "OVERDUE" } })`
   - For each Zonal Auditor, create notification: `tx.notificationQueue.create({ data: { tenantId, recipientId: za.id, type: "BM_BATCH_OVERDUE" as any, status: "PENDING", payload: { batchId, engagementId, branchName, overdueDays: Math.floor((now.getTime() - deadline.getTime()) / 86400000) } } })`
7. Log: `console.log(\`[rbia-overdue] Tenant ${tenantId}: ${overdueBatches.length} batches marked OVERDUE\`)`

The atomic transaction per batch prevents Pitfall 2 (double-firing): if notification creation fails, status rollback to PENDING means the batch will be re-processed on next cron run.
