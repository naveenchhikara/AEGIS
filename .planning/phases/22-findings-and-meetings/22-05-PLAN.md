**meeting-section.tsx** — `"use client"` component.

This component is needed because the server `meetings/page.tsx` cannot pass arrow function callbacks (onCancel, onSuccess) to the `MeetingForm` client component. MeetingSection owns the form/view toggle state internally.

**Props (all serializable — no functions):**

```typescript

interface MeetingSectionProps {
  engagementId: string;
  meetingType: "OPENING" | "EXIT";
  existingMeeting: EngagementMeetingData | null;
  teamMembers: Array<{ id: string; name: string; role: string }>;
  branchStaff?: Array<{ name: string; designation: string }>;
  canEdit: boolean;
  disabled?: boolean; // true when engagement hasn't reached the required stage
  disabledMessage?: string; // e.g., "Exit meeting available after IN_PROGRESS"
}
```

**Implementation:**

1. Internal state: `const [mode, setMode] = useState<"view" | "form">(existingMeeting ? "view" : "form")`

2. When `disabled` is true: render the `disabledMessage` in muted text, no form or view.

3. When `mode === "view"` and `existingMeeting` exists:
   - Render `<MeetingView meeting={existingMeeting} engagementId={engagementId} canEdit={canEdit} />`
   - The MeetingView has an "Edit" button — when clicked, call `setMode("form")` via a callback prop or a wrapper onClick

4. When `mode === "form"`:
   - Render `<MeetingForm engagementId={engagementId} meetingType={meetingType} existingMeeting={existingMeeting} teamMembers={teamMembers} branchStaff={branchStaff} onCancel={() => setMode("view")} onSuccess={() => { setMode("view"); router.refresh(); }} />`
   - `onCancel` and `onSuccess` are defined here in the client component — NOT passed from the server

5. When `mode === "form"` and no `existingMeeting`:
   - Show the form for creating a new meeting
   - `onSuccess` switches to "view" mode and refreshes to get the newly created meeting from the server

Import `MeetingForm` from `@/components/rbia/meeting-form` and `MeetingView` from `@/components/rbia/meeting-view`.
