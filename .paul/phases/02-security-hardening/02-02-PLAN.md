## Goal
Harden Docker containers with security constraints and add dependency vulnerability scanning to the CI pipeline and via Dependabot.

## Purpose

Before UCBs load real audit data, production containers must run with minimal privileges and known vulnerabilities in dependencies must be surfaced automatically. This reduces attack surface and ensures ongoing security hygiene.

## Output

- `docker-compose.prod.yml` hardened with security options, resource limits, and capability drops
- `ci.yml` with `pnpm audit` step that warns on vulnerabilities
- `.github/dependabot.yml` configured for automated dependency update PRs
  </objective>

## AC-1: Docker Containers Run with Restricted Privileges

```gherkin
Given docker-compose.prod.yml is updated
When the app service is defined
Then it includes:
  - security_opt: ["no-new-privileges:true"]
  - cap_drop: ["ALL"]
  - read_only: true (with tmpfs for writable dirs)
  - deploy.resources with memory limits
```

## AC-2: PostgreSQL Container Has Resource Limits

```gherkin
Given docker-compose.prod.yml is updated
When the postgres service is defined
Then it includes:
  - deploy.resources with memory limits
  - security_opt: ["no-new-privileges:true"]
  - shm_size for shared memory (required by PostgreSQL)
```

## AC-3: CI Pipeline Runs Dependency Audit

```gherkin
Given a push or PR to main
When the CI workflow runs
Then a security-audit job runs `pnpm audit --prod`

```

<task type="auto">
  <name>Task 1: Harden Docker Compose production services</name>
  <files>docker-compose.prod.yml</files>
  <action>
    Update the `app` service:
    - Add `security_opt: ["no-new-privileges:true"]`
    - Add `cap_drop: ["ALL"]`
    - Add `read_only: true`
    - Add `tmpfs` for directories Next.js needs to write:
      - `/tmp` (general temp files)
    - Add `deploy.resources.limits` with `memory: 1g`
    - Add `deploy.resources.reservations` with `memory: 512m`

    Update the `postgres` service:
    - Add `security_opt: ["no-new-privileges:true"]`
    - Add `shm_size: "256mb"` (PostgreSQL uses shared memory for query processing)
    - Add `deploy.resources.limits` with `memory: 1g`
    - Add `deploy.resources.reservations` with `memory: 256m`

    Avoid:
    - Do NOT add `cap_drop: ALL` to postgres — it needs some capabilities for its process management
    - Do NOT set `read_only: true` on postgres — it needs to write to its data directory
    - Do NOT change the existing port binding, healthcheck, or environment variables
    - Do NOT add `user:` directive to postgres — the postgres image manages its own user

  </action>
  <verify>Run `docker compose -f docker-compose.prod.yml config` to validate the compose file syntax (if docker available, otherwise validate YAML structure manually)</verify>
  <done>AC-1 and AC-2 satisfied: Both services have security constraints and resource limits</done>
</task>

<task type="auto">
  <name>Task 2: Add pnpm audit step to CI pipeline</name>
  <files>.github/workflows/ci.yml</files>
  <action>
    Add a new `security-audit` job to ci.yml that:
    - Runs on `ubuntu-latest`
    - Uses the same pnpm/node setup pattern as other jobs
    - Runs `pnpm audit --prod --audit-level=high` to check production dependencies
    - Uses `continue-on-error: true` so it reports but does not block the pipeline
    - Position it after the `lint` job in the file (but no dependency — runs in parallel)

    The job should NOT:
    - Be added to the `needs` array of the `deploy` job (advisory only, not blocking)
    - Run `pnpm audit --fix` (that modifies lockfile, not appropriate for CI)
    - Use `--audit-level=critical` (too permissive — use `high`)

    Implementation:
    ```yaml
    security-audit:
      runs-on: ubuntu-latest
      continue-on-error: true
      steps:
        - name: Checkout code
          uses: actions/checkout@v4
        - name: Install pnpm
          uses: pnpm/action-setup@v4
          with:
            version: 10
        - name: Setup Node.js
          uses: actions/setup-node@v4
          with:
            node-version: 22
            cache: "pnpm"
        - name: Install dependencies
          run: pnpm install --frozen-lockfile
        - name: Run security audit
          run: pnpm audit --prod --audit-level=high
    ```

  </action>
  <verify>Validate YAML syntax of ci.yml (check indentation and structure)</verify>
  <done>AC-3 satisfied: CI runs dependency audit on every push/PR</done>
</task>

<task type="auto">
  <name>Task 3: Create Dependabot configuration</name>
  <files>.github/dependabot.yml</files>
  <action>
    Create `.github/dependabot.yml` with two package ecosystems:

    1. **npm** — for Node.js dependencies:
       - directory: "/"
       - schedule: weekly (Monday)
       - open-pull-requests-limit: 10
       - labels: ["dependencies"]
       - ignore major versions for prisma (major upgrades need manual migration)

    2. **github-actions** — for workflow action versions:
       - directory: "/"
       - schedule: weekly (Monday)
       - open-pull-requests-limit: 5
       - labels: ["dependencies", "ci"]

    Content:
    ```yaml
    version: 2
    updates:
      - package-ecosystem: "npm"
        directory: "/"
        schedule:
          interval: "weekly"
          day: "monday"
        open-pull-requests-limit: 10
        labels:
          - "dependencies"
        ignore:
          - dependency-name: "@prisma/*"
            update-types: ["version-update:semver-major"]
          - dependency-name: "prisma"
            update-types: ["version-update:semver-major"]

      - package-ecosystem: "github-actions"
        directory: "/"
        schedule:
          interval: "weekly"
          day: "monday"
        open-pull-requests-limit: 5
        labels:
          - "dependencies"
          - "ci"
    ```

    Avoid:
    - Do NOT set `target-branch` (defaults to main, which is correct)
    - Do NOT add reviewers/assignees (not needed for small team)

  </action>
  <verify>Validate YAML syntax of dependabot.yml</verify>
  <done>AC-4 satisfied: Dependabot configured for npm and GitHub Actions</done>
</task>
