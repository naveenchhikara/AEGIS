  <action>
    Create comprehensive tests for src/lib/permissions.ts following the same pattern as state-machine.test.ts.

    Read src/lib/permissions.ts first to understand the full API:
    - Role type and enum
    - Permission type
    - ROLE_PERMISSIONS map (role → permission[])
    - getPermissions(roles: Role[]): Permission[] — union of all role permissions
    - hasPermission(roles: Role[], permission: Permission): boolean
    - requirePermission(roles: Role[], permission: Permission): void — throws if denied
    - hasAnyRole(roles: Role[], requiredRoles: Role[]): boolean
    - hasRole(roles: Role[], role: Role): boolean

    Test groups:
    1. **ROLE_PERMISSIONS structure:** Verify key roles have expected permissions
       - AUDITOR has observation:create, observation:read
       - CAE has observation:close_high_critical, admin:manage_settings
       - CEO has dashboard:read but NOT observation:create
       - AUDITEE has auditee:respond, auditee:view_own
       - SYSTEM_ADMIN has admin:manage_users

    2. **getPermissions (multi-role):** Verify union behavior
       - Single role returns that role's permissions
       - Multiple roles return deduplicated union
       - Empty roles array returns empty permissions

    3. **hasPermission:** Boolean checks
       - Returns true for granted permission
       - Returns false for denied permission
       - Multi-role user: permission from second role still returns true

    4. **requirePermission:** Throws on denied
       - Does not throw for granted permission
       - Throws Error for denied permission

    5. **hasAnyRole / hasRole:** Role checks
       - hasRole returns true/false correctly
       - hasAnyRole returns true if any match
       - hasAnyRole returns false if no match

    Import from @/lib/permissions (path alias configured in vitest.config.ts).
    Import Vitest's describe/it/expect from "vitest".

<task type="auto">
  <name>Task 3: Add Vitest to CI and configure coverage</name>
  <files>.github/workflows/ci.yml, vitest.config.ts, package.json</files>
  <action>
    **1. Add unit-test job to ci.yml:**

    Add a new job `unit-test` that:
    - Runs on ubuntu-latest
    - Uses same pnpm/node setup pattern
    - Generates Prisma client (needed for enum imports)
    - Runs `pnpm vitest run`
    - Add `unit-test` to the deploy job's `needs` array

    Place after the typecheck job:
    ```yaml
    unit-test:
      runs-on: ubuntu-latest
      steps:
        - name: Checkout code
          uses: actions/checkout@v4
        - name: Install pnpm
          uses: pnpm/action-setup@v4
          with:
            version: 10
        - name: Setup Node.js
          uses: actions/setup-node@v4
          with:
            node-version: 22
            cache: "pnpm"
        - name: Install dependencies
          run: pnpm install --frozen-lockfile
        - name: Generate Prisma Client
          run: pnpm prisma generate
        - name: Run unit tests
          run: pnpm vitest run
          env:
            SKIP_ENV_VALIDATION: "1"
    ```

    Update deploy job: `needs: [lint, typecheck, build, unit-test]`

    **2. Update vitest.config.ts for coverage:**

    Add coverage configuration using v8 provider:
    ```ts
    coverage: {
      provider: "v8",
      include: ["src/lib/**/*.ts", "src/services/**/*.ts"],
      exclude: ["src/lib/__tests__/**", "src/services/**/__ tests__/**"],
      reporter: ["text", "text-summary"],
    }
    ```

    **3. Add npm scripts to package.json:**

    Add these scripts (read package.json first to find the scripts section):
    - `"test:unit": "vitest run"`
    - `"test:coverage": "vitest run --coverage"`

    Avoid:
    - Do NOT install @vitest/coverage-v8 — it's built into Vitest 3+
    - Do NOT modify the existing test:e2e scripts
    - Do NOT make unit-test job continue-on-error (it must block deploys)

  </action>
