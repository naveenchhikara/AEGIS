<objective>
## Goal
Add security response headers (CSP, HSTS, Permissions-Policy, X-Content-Type-Options, X-Frame-Options, Referrer-Policy) to all AEGIS responses via Next.js config.

## Purpose

AEGIS handles sensitive UCB audit data. Before onboarding real banks, the platform must defend against XSS injection, clickjacking, MIME sniffing, and protocol downgrade attacks. Security headers are the first line of browser-level defense.

## Output

- `next.config.ts` updated with `headers()` configuration
- All responses include 6 security headers
- CSP configured to allow AEGIS's runtime needs (Tailwind inline styles, Recharts SVG, next-intl)
  </objective>

<task type="auto">
  <name>Task 1: Configure security headers in next.config.ts</name>
  <files>next.config.ts</files>
  <action>
    Add a `headers()` async function to the Next.js config that returns security headers for all routes.

    Headers to add (applied to all routes via `source: "/(.*)"` pattern):

    1. **Content-Security-Policy** — Must be permissive enough for the stack:
       - `default-src 'self'`
       - `script-src 'self' 'unsafe-eval' 'unsafe-inline'` (Next.js requires unsafe-eval in dev, unsafe-inline for inline scripts)
       - `style-src 'self' 'unsafe-inline'` (Tailwind CSS and Radix UI inject inline styles)
       - `img-src 'self' data: blob: https:` (allow data URIs for SVGs, blob for PDF preview, HTTPS for external images)
       - `font-src 'self'` (local fonts only)
       - `connect-src 'self' https://aegis.nexlyadvisory.com` (API calls to self)
       - `frame-ancestors 'none'` (replaces X-Frame-Options for CSP3)
       - `base-uri 'self'`
       - `form-action 'self'`
       - `object-src 'none'`
       - Note: `unsafe-eval` only in development — use process.env.NODE_ENV check

    2. **Strict-Transport-Security**: `max-age=63072000; includeSubDomains; preload` (2 years)

    3. **X-Content-Type-Options**: `nosniff`

    4. **X-Frame-Options**: `DENY` (legacy browsers that don't support CSP frame-ancestors)

    5. **Referrer-Policy**: `strict-origin-when-cross-origin`

    6. **Permissions-Policy**: `camera=(), microphone=(), geolocation=(), payment=(), usb=()`

    Implementation approach:
    - Define headers array as a const
    - Add `async headers()` to nextConfig object
    - For CSP, build the directive string from an array of parts for readability
    - Use `process.env.NODE_ENV === 'development'` to add `unsafe-eval` to script-src only in dev

    Avoid:
    - Do NOT add headers via middleware (middleware runs on Edge, headers() is more reliable for static assets too)
    - Do NOT block `unsafe-inline` for styles — Tailwind and Radix require it
    - Do NOT add `upgrade-insecure-requests` directive — it breaks localhost development

  </action>
  <verify>Run `SKIP_ENV_VALIDATION=1 DATABASE_URL="postgresql://x:x@localhost:5432/x" pnpm build` and confirm build succeeds</verify>
  <done>AC-1 satisfied: All 6 security headers configured. AC-3 satisfied: Build succeeds.</done>
</task>
