**1. Create `src/components/sampling/criteria-config-form.tsx`:**

"use client" component. This is the core UI for SMPL-01, SMPL-02, and SMPL-03.

Props:

```typescript
interface CriteriaConfigFormProps {
  engagementId: string;
  moduleCode: string;
  existingConfig: {
    sampleSizePct: number;
    criteriaBuckets: BucketAllocation[];
    isLocked: boolean;
    sampleGenerated: boolean;
  } | null;
  portfolioCount: number;
  canEdit: boolean; // false for auditors (SMPL-03)
}
```

**UI structure:**

**When `canEdit` is false (auditor view — SMPL-03):**

- Render a read-only Card displaying the criteria table with no input controls
- Show bucket names and percentages as plain text in a table
- Show sample size percentage and calculated count as text
- No buttons, no disabled inputs — truly no edit controls per CONTEXT.md
- If no config exists, show a muted message: "Sampling criteria have not been configured yet."

**When `canEdit` is true (HIA view — SMPL-01, SMPL-02):**

a) **Sample size input section:**

- Label: "Overall Sample Size"
- Number input for `sampleSizePct` (1-100, step 0.5)
- Next to it, a calculated display: "{pct}% of {portfolioCount} accounts = {Math.round(portfolioCount \* pct / 100)} accounts"
- Use shadcn/ui Input component

b) **Criteria bucket table:**

- 5 rows, one per fixed bucket: NEWLY_SANCTIONED, AMOUNT_WISE, AGE_WISE, DPD_WISE, PRIOR_OBSERVATIONS
- Column 1: Bucket name (human-readable: "Newly Sanctioned", "Amount-wise", "Age-wise", "DPD-wise", "Prior Observations")
- Column 2: Description (static text explaining the bucket)
- Column 3: Number input for percentage (0-100, step 1)
- Column 4: Calculated account count for this bucket: Math.round(totalSampleCount \* bucketPct / 100)
- Use shadcn/ui Table component for the layout
- State: useState for the 5 bucket percentages + sample size pct

c) **Running total row:**

- Below the table, show: "Total: {sum}%"
- Color: green text when sum === 100, red text when sum !== 100
- Disable Save button when sum !== 100

d) **Action buttons:**

- "Save Criteria" button — calls `saveSamplingCriteria` server action. Disabled when sum !== 100 or no changes
- "Generate Sample" button — calls `generateSampleAction` server action. Shown only when criteria are saved. Include a confirmation: "This will select {n} accounts from the portfolio. Previous sample will be replaced."
- Both use `useTransition()` for pending state with loading spinner
- After successful generation, show a toast (sonner) with the result: "Sample generated: {n} accounts selected" + any warnings

e) **Redistribution warnings display:**

- After generation, if warnings exist, render an Alert (shadcn/ui) with variant "warning" (amber/yellow)
- List each warning: "Newly Sanctioned: {filled}/{requested} filled, {shortfall} redistributed to {redistributedTo}"

f) **Locked state:**

- When config.sampleGenerated is true, show all inputs as disabled with a banner: "Criteria are locked. To reconfigure, click Unlock."
- "Unlock" button (if canEdit) — resets `isLocked` and `sampleGenerated` via a server action call to saveSamplingCriteria with unlocked state
