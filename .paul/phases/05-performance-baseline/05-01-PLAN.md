<objective>
## Goal
Install bundle analyzer, generate a baseline bundle report, identify optimization opportunities, and document the current performance baseline before pilot onboarding.

## Purpose

AEGIS has 600+ source files and a 316MB build output. Before onboarding real UCBs, we need visibility into bundle composition to identify any bloated dependencies or code-splitting opportunities. This plan establishes the tooling and captures a baseline — actual optimizations (if needed) come from the analysis results.

## Output

- @next/bundle-analyzer installed and configured
- Bundle analysis report generated (HTML treemap)
- Performance baseline documented (build size, key route sizes, largest dependencies)
- Optimization recommendations captured for future action
  </objective>

<task type="auto">
  <name>Task 1: Install and configure @next/bundle-analyzer</name>
  <files>package.json, next.config.ts</files>
  <action>
    1. Install the bundle analyzer as a dev dependency:
       - `pnpm add -D @next/bundle-analyzer`

    2. Update next.config.ts to conditionally wrap with bundle analyzer:
       - Import: `import bundleAnalyzer from "@next/bundle-analyzer"`
       - Create analyzer wrapper: `const withBundleAnalyzer = bundleAnalyzer({ enabled: process.env.ANALYZE === "true" })`
       - Chain it into the existing config wrapping:
         Currently: `withSentryConfig(withNextIntl(nextConfig), sentryOptions)`
         After: `withSentryConfig(withBundleAnalyzer(withNextIntl(nextConfig)), sentryOptions)`
       - The analyzer only activates when ANALYZE=true is set

    3. Add an analyze script to package.json:
       - `"build:analyze": "ANALYZE=true next build"`
       - This provides a convenient shortcut for developers

    Avoid:
    - Do NOT enable the analyzer by default (only when ANALYZE=true)
    - Do NOT change the existing config wrapping order beyond adding the analyzer
    - Do NOT install @next/bundle-analyzer as a production dependency (dev only)
    - Do NOT modify the Dockerfile or CI pipeline (analyzer is for local dev use)

  </action>
  <verify>
    - pnpm build succeeds without ANALYZE set (normal build, no analyzer)
    - ANALYZE=true pnpm build generates bundle analysis HTML
    - package.json has build:analyze script
  </verify>
  <done>AC-1 satisfied (analyzer configured), AC-2 satisfied (script available)</done>
</task>
