<objective>
## Goal
Create automated PostgreSQL backup system with S3 offsite storage, cron scheduling, and a tested restore procedure.

## Purpose

The VPS uses a Docker volume for PostgreSQL data. If the VPS is lost, all tenant data is lost — there are zero backups today. This is a critical gap before any real UCB loads production data. The S3 bucket already has a `backups/` lifecycle rule (→ Glacier at 30d, expire at 90d) configured in CDK.

## Output

- `deploy/backup.sh` — Backup script that pg_dumps, compresses, uploads to S3, and prunes old local copies
- `deploy/restore.sh` — Restore script that downloads from S3 and restores into PostgreSQL
- Updated `docker-compose.prod.yml` — Backup volume mount for the app container
- DR runbook section in `deploy/README.md`
  </objective>

## AC-1: Automated Backup Creation

```gherkin
Given the PostgreSQL container is running
When deploy/backup.sh is executed
Then a compressed pg_dump (.sql.gz) is created in /backups/ with timestamp naming
And the backup file is uploaded to S3 under the backups/ prefix
And local backups older than 7 days are pruned
And the script exits 0 on success or non-zero on failure with error logging
```

## AC-2: S3 Upload with AWS CLI

```gherkin
Given AWS credentials are available (AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY)
And the S3 bucket name is configured
When the backup script uploads a file
Then the file appears in s3://{bucket}/backups/aegis-{date}.sql.gz
And the upload uses server-side encryption (SSE-S3)
```

## AC-3: Database Restore from Backup

```gherkin
Given a backup file exists in S3 or locally
When deploy/restore.sh is executed with a backup filename
Then the script downloads the backup from S3 (if not local)
And drops and recreates the target database
And restores the pg_dump into PostgreSQL
And verifies the restore by querying table count
```

## AC-4: Cron Schedule

```gherkin
Given the backup script is deployed on the VPS
When the system cron runs at 02:00 IST daily
Then a backup is created and uploaded to S3
And backup success/failure is logged to /var/log/aegis-backup.log
```

<task type="auto">
  <name>Task 1: Create backup script</name>
  <files>deploy/backup.sh</files>
  <action>
    Create deploy/backup.sh that:
    1. Sources environment from .env.production (POSTGRES_USER, POSTGRES_PASSWORD, POSTGRES_DB, S3_BUCKET_NAME, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_REGION)
    2. Creates /backups/ directory if not exists
    3. Runs pg_dump via docker exec on aegis-postgres container:
       `docker exec aegis-postgres pg_dump -U $POSTGRES_USER -d $POSTGRES_DB | gzip > /backups/aegis-$(date +%Y%m%d-%H%M%S).sql.gz`
    4. Verifies backup file is > 0 bytes
    5. Uploads to S3: `aws s3 cp /backups/$FILENAME s3://$S3_BUCKET_NAME/backups/$FILENAME --sse AES256`
    6. Prunes local backups older than 7 days: `find /backups -name "aegis-*.sql.gz" -mtime +7 -delete`
    7. Logs all operations with timestamps to stdout (for cron log capture)
    8. Exits with appropriate return code (0 success, 1 failure)

    Make the script executable (chmod +x).
    Use set -euo pipefail for safety.
    Include a BACKUP_DIR variable that defaults to /backups but can be overridden.
    Include a RETENTION_DAYS variable that defaults to 7.

  </action>
  <verify>shellcheck deploy/backup.sh passes (or manual review for bash best practices)</verify>
  <done>AC-1 and AC-2 satisfied: Script creates compressed backup, uploads to S3, prunes old files</done>

<task type="auto">
  <name>Task 2: Create restore script</name>
  <files>deploy/restore.sh</files>
  <action>
    Create deploy/restore.sh that:
    1. Accepts a backup filename as argument (required)
    2. Sources environment from .env.production
    3. If file doesn't exist locally, downloads from S3:
       `aws s3 cp s3://$S3_BUCKET_NAME/backups/$FILENAME /backups/$FILENAME`
    4. Confirms with user before proceeding (echo warning, read -p confirmation)
    5. Drops and recreates the database:
       `docker exec aegis-postgres psql -U $POSTGRES_USER -c "DROP DATABASE IF EXISTS $POSTGRES_DB;"`
       `docker exec aegis-postgres psql -U $POSTGRES_USER -c "CREATE DATABASE $POSTGRES_DB;"`
    6. Restores: `gunzip -c /backups/$FILENAME | docker exec -i aegis-postgres psql -U $POSTGRES_USER -d $POSTGRES_DB`
    7. Verifies by counting tables:
       `docker exec aegis-postgres psql -U $POSTGRES_USER -d $POSTGRES_DB -c "SELECT count(*) FROM information_schema.tables WHERE table_schema = 'public';"`
    8. Lists available backups if called with --list flag (local + S3)

    Make executable. Use set -euo pipefail.
    Print clear status messages at each step.

  </action>
  <verify>Manual review of script logic and error handling</verify>
  <done>AC-3 satisfied: Restore script downloads from S3, restores DB, verifies table count</done>
</task>

  <action>
    Add a "Backup & Disaster Recovery" section to deploy/README.md covering:

    1. **Backup Setup:**
       - Install AWS CLI on VPS: `apt install awscli`
       - Create /backups directory: `mkdir -p /backups`
       - Set up cron job:
         `echo "0 2 * * * cd /path/to/aegis && ./deploy/backup.sh >> /var/log/aegis-backup.log 2>&1" | crontab -`
       - Verify cron: `crontab -l`

    2. **Manual Backup:**
       - Run: `./deploy/backup.sh`
       - Check S3: `aws s3 ls s3://$S3_BUCKET_NAME/backups/`

    3. **Restore Procedure:**
       - List backups: `./deploy/restore.sh --list`
       - Stop app: `docker compose -f docker-compose.prod.yml stop app`
       - Restore: `./deploy/restore.sh aegis-20260221-020000.sql.gz`
       - Run migrations if needed: `docker exec aegis-app npx prisma db push`
       - Start app: `docker compose -f docker-compose.prod.yml start app`
       - Verify: check /api/health

    4. **Monitoring:**
       - Check backup log: `tail -f /var/log/aegis-backup.log`
       - Check last backup age: `ls -la /backups/ | tail -1`

    5. **Retention Policy:**
       - Local: 7 days (pruned by backup script)
       - S3 Standard: 30 days (then transitions to Glacier)
       - S3 Glacier: 60 days (then expired — 90 days total)

    Do NOT remove existing content in README.md — append the new section.

  </action>
