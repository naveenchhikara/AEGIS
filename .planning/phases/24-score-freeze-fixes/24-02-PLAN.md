**Bug 1: Fix ScoreDrilldownWrapper to handle array format**

The `freezeRbiaScore` server action stores `scoringTreeSnapshot` as an ARRAY of module nodes:

```typescript
const scoringTreeSnapshot = moduleNodes.map(function serializeNode(n) { ... });
```

But `ScoreDrilldownWrapper` casts it as a single root node and accesses `tree.children`:

```typescript
const tree = scoringTree as ScoredNodeSnapshot;
// tree.children is undefined because scoringTree is an array, not a node
```

   ```typescript
   import {

   ```

   ```typescript
   // scoringTreeSnapshot is stored as an array of module nodes by freezeRbiaScore
   ```

   ```typescript
   const findModuleNode = useCallback(
   ```

**Bug 2: Add name field to serializeNode in freeze.ts**

The `serializeNode` function (lines 220-232) omits `name`. The `nodeMap` (lines 165-182) builds `ScoredNode` entries but `ScoredNode` type does not have `name`. The fix needs to:

1. In `freeze.ts`, extend the nodeMap entry type to carry `name`. The current type is `ScoredNode & { depth: number; parentId: string | null }`. Change to also include `name`:

   At line 165, change the Map type:

   ```typescript
   const nodeMap = new Map<
     string,
     ScoredNode & { depth: number; parentId: string | null; name: string }
   >();
   ```

2. At line 171, add `name` to the nodeMap entry (after the `code: n.code` line):

   ```typescript
   nodeMap.set(n.id, {
     nodeId: n.id,
     code: n.code,
     name: n.name, // <-- ADD THIS LINE
     weight: Number(n.weight),
     isCritical: n.isCritical,
     isLeaf: n.isLeaf,
     scoreLabel: (resp?.scoreLabel as any) ?? null,
     children: [],
     depth: n.depth,
     parentId: n.parentId,
   });
   ```

   Note: `ScoredNode` type from `rbia-scoring-engine.ts` may not have a `name` property. Since we're using intersection type (`ScoredNode & { ... }`), adding `name` to the intersection is valid. If TypeScript complains about the `name` property not being in `ScoredNode`, cast the object: use `as ScoredNode & { depth: number; parentId: string | null; name: string }`.

3. In the `serializeNode` function (lines 220-232), add `name` to the returned object. The function parameter is typed as `ScoredNode`, but the actual values in `moduleNodes` come from `nodeMap` which has the extended type. Cast as needed:

   ```typescript
   const scoringTreeSnapshot = moduleNodes.map(function serializeNode(
     n: ScoredNode & { name?: string },
   ): any {
     return {
       nodeId: n.nodeId,
       code: n.code,
       name: (n as any).name ?? undefined, // Include name for human-readable display
       weight: n.weight,
       isCritical: n.isCritical,
       isLeaf: n.isLeaf,
       scoreLabel: n.scoreLabel,
       children: n.children.map(serializeNode),
     };
   });
   ```

   The `(n as any).name` cast handles the fact that child nodes (from `n.children`) are `ScoredNode[]` which may not have `name` on the type. The recursive call processes children that were also built with `name` in nodeMap, so the value will be present at runtime even if the type doesn't declare it.

**Important backward compatibility note:** Existing frozen snapshots in the DB will NOT have the `name` field. The `ScoreDrilldownWrapper` already handles this with `child.name ?? child.code` fallback. The `ScoreDrilldown` component also uses `node.name || node.code` (line 158). No additional fallback changes needed.
