  <action>
    Review the data flow for each transition point:

    1. RAM → Branch scoring:
       - Does computeRamAssessment() update Branch.ramScore?
       - Does approveAssessment() lock the assessment properly?

    2. Planning → Engagement creation:
       - Does generateAnnualPlan() create AuditEngagement records?
       - Can users create engagements manually from /audit-execution/create?
       - Is the plan-to-engagement link preserved?

    3. Execution → Observation creation:
       - How are observations created from examination items? Auto or manual?
       - Does submit-examination-response link to observation creation?
       - Is engagementId carried through to the observation?

    4. Observation state machine:
       - Review ALL 8 transitions in state-machine.ts
       - Check permission guards match CLAUDE.md documentation
       - Verify optimistic locking (version field) works
       - Check: what happens at ISSUED transition? Is ComplianceItem auto-created?

    5. Observation → Compliance item:
       - Is there auto-creation logic when observation reaches ISSUED?
       - If not, how does compliance item get created?
       - Is the observation-compliance link bidirectional?

    6. Compliance lifecycle:
       - Branch response → ZAC review → ACE review → ACB → Closed
       - Are all transitions implemented in actions?
       - Do escalation levels auto-increment on overdue?

    7. Engagement completion:
       - Is there an action to mark engagement as COMPLETED?
       - What triggers engagement status changes?

    For each gap, record with severity.

  </action>
