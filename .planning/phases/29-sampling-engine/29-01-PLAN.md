<feature>
  <name>Sampling Engine — Deterministic Bucket-Fill Algorithm</name>
  <files>src/lib/sampling-engine.ts, src/lib/__tests__/sampling-engine.test.ts</files>
  <behavior>
    **Types:**
    - SamplingInput: { accounts: LoanAccountForSampling[], sampleSizePct: number, criteriaBuckets: BucketAllocation[] }
    - SampledAccount: { accountId: string, bucket: string } (which bucket selected this account)
    - RedistributionWarning: { bucket: string, requested: number, filled: number, shortfall: number, redistributedTo: string }
    - SamplingResult: { sampledAccounts: SampledAccount[], warnings: RedistributionWarning[], totalRequested: number, totalSelected: number }

    **Core behavior (test cases):**

    1. Basic sampling — 100 accounts, 10% sample size, even 20% per bucket → selects 10 accounts, 2 per bucket
    2. Bucket allocation math — sample count = Math.round(totalAccounts * sampleSizePct / 100), per-bucket = Math.round(sampleCount * bucket.pct / 100)
    3. Deterministic ordering within buckets:
       - NEWLY_SANCTIONED: accounts sanctioned within last 12 months, ordered by DPD desc → outstanding desc → sanctionDate asc
       - AMOUNT_WISE: all accounts ordered by outstanding desc → DPD desc → sanctionDate asc
       - AGE_WISE: all accounts ordered by sanctionDate asc (oldest first) → DPD desc → outstanding desc
       - DPD_WISE: all accounts ordered by DPD desc → outstanding desc → sanctionDate asc
       - PRIOR_OBSERVATIONS: accounts where hasPriorObservations=true, ordered by DPD desc → outstanding desc
    4. No duplicates — account selected by first bucket is excluded from subsequent bucket pools
    5. Overflow redistribution — bucket has fewer eligible accounts than requested:
       - Take all available accounts in that bucket
       - Calculate shortfall
       - Redistribute shortfall to next-largest bucket (by pct, then alphabetical bucket name for ties)
       - Return warning with details
    6. Cascading overflow — if redistribution target also has insufficient accounts, cascade to next bucket
    7. Empty portfolio — 0 accounts → empty result, no errors
    8. Single bucket at 100% — all sample comes from one bucket
    9. Rounding — verify total selected does not exceed sample count (handle Math.round edge cases)
    10. Prior observations empty — no accounts with flag → overflow to next bucket with warning

  </behavior>
  <implementation>
    1. Define TypeScript types for all inputs/outputs in src/lib/sampling-engine.ts
    2. Export `generateSample(input: SamplingInput): SamplingResult`
    3. Algorithm:
       a. Calculate totalSampleCount = Math.round(accounts.length * sampleSizePct / 100)
       b. Calculate per-bucket counts from bucket.pct, ensuring sum does not exceed totalSampleCount
       c. Build eligible-account pools per bucket using classification logic
       d. Process buckets in order of their pct (largest first) — for each:
          - Filter out already-selected accounts
          - Sort by deterministic criteria
          - Take min(requested, available) accounts
          - If shortfall, record RedistributionWarning
       e. After all buckets processed, redistribute shortfalls to buckets with remaining capacity
       f. Return SamplingResult
    4. The `hasPriorObservations` flag must be accessible on LoanAccountForSampling — add it to the interface (boolean field, Phase 28 adds to LoanAccount model or metadata)
  </implementation>
</feature>
